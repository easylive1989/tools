# Notion 買賣損益與持股

從交易來源表重新計算先進先出成本，更新「收益」與「持股」兩張 Notion 表。
程式只讀取來源交易，不修改來源紀錄。價格、成本及損益的幣別為新台幣。

## 計算規則

- 每個「券商 + 股票代號」獨立 FIFO；名稱第一個空白前是股票代號。
- 每筆賣出一列。淨損益 = 賣出金額 − 配對買進成本 − 分攤買進費用 − 賣出費用。
- 來源的「手續費」已含稅，不再另估證交稅。部分賣出依股數分攤買進費用，
  四捨五入至分，未分攤餘額留在剩餘批次，確保費用不重複扣除或遺失。
- 年度按台灣時間的賣出日期，年度列加總已呈現的逐筆金額；不含股息、未實現損益。
- 「成本報酬率」= 淨損益 / 已實現含費用成本；不是帳戶年度報酬率，不對逐筆百分比加總。
  百分比四捨五入至小數點後兩位；成本為零時留空。
- 同日期、同方向交易依來源建立時間、頁面 ID 決定穩定順序。來源未記錄盤中成交先後，
  同日多筆買進的 FIFO 細項可能與券商批次順序不同；要精確指定順序，請在「時間」填時分秒。
  同股票同券商同日同時有買入與賣出，必須填實際時間，否則停止同步。
- 「持股」按券商與股票顯示剩餘股數、剩餘含費用成本、每股成本及買進批次連結。
  不抓即時股價，不計市值或未實現損益。
- 本工具只支援一般買入／賣出；拆股、合股、配股、移轉、融券或多幣別必須先另行建模，
  不可把它們當作一般買賣自動推算。負庫存或欄位缺漏會停止整次同步，保留先前結果。

## Notion 表格

來源必須有：`Name`（標題）、`交易`（買入/賣出 select）、`價格`、`股數`、
`手續費`（number）、`時間`（date）、`券商`（select）。目標表必須有 `Name` 標題欄。
其他目標欄位由首次 `--apply` 新增，不移除既有欄位。

收益檢視請設定：

- **賣出明細**：`有效 = true`、`類型 = 賣出明細`，按賣出日期新到舊。
- **年度收益**：`有效 = true`、`類型 = 年度彙總`，按年度新到舊。
- **按年檢視**：僅有效賣出明細，按年度分組。不要將年度彙總列與明細一起加總。
- **目前持股**：`有效 = true`，按券商與股票代號排序。

收益紅色「▲ 獲利」、綠色「▼ 虧損」。每筆都有來源賣出關聯與 FIFO 買進配對明細。
年度列、逐筆列及持股列都有固定同步鍵；修改來源後重跑會更新原列。
來源刪除或股票售罄時，舊衍生列標記 `有效 = false`，保留紀錄，不刪使用者自行新增的列。
`最後更新` 是該列內容最後改變的時間；每次排程是否成功請看 GitHub Actions。

## 執行

```bash
pip install -r notion_portfolio/requirements.txt
export NOTION_SECRET='...'
export NOTION_TRADES_DATA_SOURCE_ID='...'
export NOTION_PROFIT_DATA_SOURCE_ID='...'
export NOTION_HOLDINGS_DATA_SOURCE_ID='...'
python notion_portfolio/sync.py           # 唯讀檢查
python notion_portfolio/sync.py --apply   # 更新 Notion
python -m unittest discover -s notion_portfolio/tests -v
```

ID 是 Notion **data source ID**，不是 database 容器 ID；三個來源必須互不相同。
在 Notion 將三張表連接給同一個 integration，授予來源讀取、目標讀寫權限。
不提交金鑰、私人資料庫 ID、交易明細、實際金額或私人報表。
選用 `--report /private/path/report.local.json` 可另存私人摘要；請勿上傳 CI artifact。

## 每日自動同步

`.github/workflows/sync-notion-portfolio.yml` 每天台灣時間 **08:15、20:15** 執行，
也可用 workflow_dispatch 手動啟動。GitHub 排程可能延遲，不保證準點；公開儲存庫長期無活動
可能停用排程，屆時需重新啟用。資料不需要透過本機 Mac 同步。

GitHub Actions repository secrets 設定三個 `NOTION_*_DATA_SOURCE_ID`，並沿用儲存庫既有
`NOTION_SECRET`；不將交易明細寫入公開日誌。
執行前先跑測試；並行執行會排隊。請勿同時從本機執行 `--apply`，避免與雲端競爭。
遇到 API 部分失敗時可能暫時有部分已更新的列；修正問題並重跑可收斂，不需清空資料庫。
建立頁面的模糊網路失敗不盲目重試，下一次先重新查詢既有頁面以避免重複建立。
